### `amps/codegen/generate.py` — the emit/check driver

**Public API (the two functions M2b calls):**

```python
def emit_module(name: str, build: Callable[..., str], **params: object) -> Path:
    """Write build(**params)'s DSL source (license header + GENERATED banner
    prepended) to the COMMITTED core/generated/{name}.py, then load it
    (validating the emitted source is at least importable) before returning
    its path. Run this offline, by a developer ... NOT from the test suite."""

def check_regenerated(name: str, build: Callable[..., str], **params: object) -> None:
    """Drift guard: assert core/generated/{name}.py (already committed to disk)
    is byte-identical to what build(**params) currently produces. Raises
    AssertionError with a unified diff on mismatch. Read-only -- never calls
    emit_module/writes to disk."""
```

- `emit_module` is **developer-run/offline**, writes the committed file, then `load_generated_module` to validate importability. `check_regenerated` is the **read-only pytest counterpart** — re-runs the builder in memory and asserts byte-equality against the committed file; on drift raises `AssertionError` with a `difflib.unified_diff`. A drifted generator **fails loudly** rather than silently rewriting the committed file.
- `_render_module` = `_LICENSE_HEADER + "\n" + _banner(build, params) + "\n" + body`, then `_finalize`.
- **`_finalize`** pipes builder output through `ruff check --fix --exit-zero` then `ruff format` (same two steps/order as the repo pre-commit hooks), via `_ruff_command` (plain `ruff` on PATH, else `uv run --group dev --frozen --isolated ruff`). So committed generated files are pre-commit-clean by construction and `check_regenerated`'s comparison stays apples-to-apples regardless of the builder's own formatting.
- **`load_generated_module(name)`** uses `importlib.util.spec_from_file_location` (not plain `import`) to guarantee a fresh module object each call (gt4py's `@gtx.field_operator` needs a real file on disk for `inspect.getsource`). Generated package: `icon4py.model.atmosphere.subgrid_scale_physics.amps.core.generated`; dir = `amps/core/generated/`.

**GENERATED banner + drift-guard pattern** (`_banner`):
```python
return f"# GENERATED by codegen/generate.py -- do not edit.\n# Builder {build_name} -- {tail}\n"
```
The banner is deliberately written as prose-with-trailing-period (`"Builder X -- params: ...  ."`) **not** as `name(params)` / `key=value`, because ruff's ERA001 (commented-out-code) rule flags any comment that parses as valid Python — that would bake a hard `ruff check` failure into every committed file. M2b's builder must respect this.

**BINDING design constraint (quoted verbatim from the module docstring):**
> every builder passed to `emit_module` MUST emit SPLIT operators — one `@gtx.field_operator` per bin GROUP of at most 8 consecutive bins, never one monolithic operator spanning an entire hydrometeor category's bins. `spikes/spike_b_collection_codegen.py` measured a single unrolled 40-bin collection-kernel operator's `gtfn_cpu` compile at ~2579s (~43 minutes) — this is the concrete cost SPLIT operators avoid. Shared 4-D array convention for all state bundles: **`values: np.ndarray` shaped `(nprops, nbins, ncat, npoints)`, float64.** Axis 0 (property) is Fortran 1-based PPV order. `ncat` is only ever exercised at 1 (`to_fields`/`from_fields` raise `NotImplementedError` for `ncat != 1`).

```python
    rmt_q, rcon_q, rmat_q, rmas_q."""
    GROUP: ClassVar[str] = "liquid"
    PROPS: ClassVar[tuple[enum.IntEnum, ...]] = _sorted_props(index_maps.LiquidPPV)
```

**Per-bin mass/number layout** — the four liquid PPV slots (from `amps/core/index_maps.py`, `LiquidPPV`, Fortran 1-based; `.py_idx` = value−1):
- `rmt_q = 1` — total mass (per bin), py_idx 0
- `rcon_q = 2` — number concentration (per bin), py_idx 1
- `rmat_q = 3` — total aerosol mass, py_idx 2
- `rmas_q = 4` — soluble aerosol mass, py_idx 3

So per-bin mass = `liquid.values[LiquidPPV.rmt_q.py_idx, bin, 0, :]`, per-bin number = `...[rcon_q.py_idx, ...]`. **Water-only mass per bin = `rmt_q − rmat_q`** (used everywhere: warm_loop, vapor_deposition tests). These are already **per-unit-moist-air-mass mixing ratios** (not per-volume) — critical unit convention that bit the activation port (see §3, C1 fix).

Field-conversion convention (`to_fields`/`from_fields`): one `(Cell,K)` gt4py field per (property,bin), named `f"{GROUP}_{prop_name}_{bin:02d}"` (e.g. `"liquid_rmt_q_00"`); point index `p = cell*nlev + level` (row-major). Round-trip is lossless/exact.

`ThermoState` reuses the same machinery pinned to `nbins=1` (`ThermoProp` enum). **UNIT CONTRACT (M2a hardening, see §3):** `ptotv` CGS dyn/cm², `moist_denv` CGS g/cm³, `tv`/`thv`/`thetav` K, `qvv` dimensionless — canonicalized once at the two producers; consumers read AS-IS.

## 4. muphys collection precedent — none; AMPS collection is the first

**muphys warm-rain is BULK, no bins.** `muphys/core/transitions.py::cloud_to_rain` (`_cloud_to_rain`) is a single `@gtx.field_operator` over scalar `(Cell,K)` fields:
```python
def _cloud_to_rain(t: fa.CellKField[ta.wpfloat], qc: ..., qr: ..., nc: ta.wpfloat) -> fa.CellKField[ta.wpfloat]:
    # SB2001 autoconversion + accretion, phi-function
    tau = maximum(TAU_MIN, minimum(ONE - qc/(qc+qr), TAU_MAX))
    ...
    xau = AU_KERNEL * power(qc*qc/nc, TWO) * (...)   # autoconversion
    xac = AC_KERNEL * qc * qr * power(tau/(tau+C_PHI), FOUR)  # accretion
    return where((qc > QMIN_AC) & (t > tfrz_hom), xau + xac, ZERO)
```
`grep` for `n_bin`/`nbins`/`bin_grid`/`per-bin` across all of muphys src returns **nothing**. muphys has no bin dimension at all — it is the Seifert-Beheng-style two-category bulk (qc/qr/nc scalars), no size distribution, no pair interactions. Every muphys "transition" (`cloud_to_rain`, `rain_to_graupel`, `snow_to_rain`, etc.) is a scalar bulk-rate operator.

**No icon4py precedent for an O(n²) bin-interaction kernel exists in committed code.** The only bin-pair collection artifact anywhere is the throwaway spike `amps/spikes/spike_b_collection_codegen.py`, which explicitly frames itself as an architectural feasibility gate:
> code-generate an unrolled bin-pair collection (coalescence) kernel and measure ... compile + run cost at nbins = 8, 20, 40. ... Structure (**nbins² pair terms scattered to ≤2 destination bins each, plus nbins × nbins loss sums) matches the real AMPS coalescence shape.** This is the compile-time gate for the whole AMPS port architecture (spec §9 risk 1): can a single generated, fully-unrolled field_operator for the 40-bin case even compile on gtfn_cpu in a bounded time?

That spike is what established the ≤8-bin SPLIT-operator mandate (the 40-bin monolith compiled in ~2579s / ~43min). **AMPS M2b's collection bin-pair kernel is therefore the first production O(n²) bin-interaction kernel in icon4py** — it is the first real (non-demo) consumer of the M1 codegen pipeline, and it must chunk-by-destination-bin (≤8 bins/operator) from the start.
